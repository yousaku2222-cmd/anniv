## 2. 画面フロー

```
起動
 └ splash（初回のみ: 通知許可 → サンプルイベントを見る）
 └ home（イベント一覧）
      ├─ カード tap → detail（イベント詳細）
      ├─ FAB ＋ → create-1 → create-2 → create-3 → create-4 → create-5 → [保存] → toast → home
      ├─ ヘッダー右 📦 → widget（ウィジェット設定）
      └─ ヘッダー右 ⚙ → settings（設定）
 settings の「ダークモード」切替は全画面へ即時反映（html.dark トグル）
```

## 4. サンプルデータ（`data/sample-events.json` と同一）

基準日 **2026-08-30** 時点の残り日数。`repeat: yearly` は次回発生日を自動計算する（基準日は初回日付）。

| # | title | type | targetDate | repeat | countMode | group | 基準日時点表示 | 通知 |
|---|---|---|---|---|---|---|---|---|
| 1 | 推しのライブ | oshi | 2026-09-06 | none | daysLeft | oshi | あと 7 日 | 7日前 09:00 ほか |
| 2 | 付き合った記念日 | anniversary | 2026-09-18 | yearly | daysLeft | couple | あと 19 日 | 当日 09:00 ほか |
| 3 | 英検準2級 1次試験 | exam | 2026-10-04 | none | daysLeft | dai | あと 35 日 | 7日前 09:00 ほか |
| 4 | 年末年始 沖縄旅行 | trip | 2026-12-30 | none | daysLeft | family | あと 122 日 | 7日前 09:00 ほか |
| 5 | ママの誕生日 | birthday | 2027-02-03 | yearly | daysLeft | family | あと 157 日 | 当日 09:00 ほか |
| 6 | 赤ちゃん 100日記念 | custom | 2026-05-12 | none | daysSince | family | +110 日目 | なし |

グループ（`groupId`）: `family`=家族 / `couple`=カップル / `oshi`=推し活 / `dai`=大事な日（Home タブは「すべて」+ この 4 つ）

### 4-1 マイルストーン（例: 旅行 12/30 / 英検 10/04）

| マイルストーン | 定義日 | 基準日比 |
|---|---|---|
| 90日前 | targetDate − 90日 | あと32日で90日前（10/01） |
| 30日前 | targetDate − 30日 | あと92日で30日前（11/30） |
| 7日前 | targetDate − 7日 | あと115日で7日前（12/23） |

※ モックの詳細画面に載せた「次のマイルストーン」文言はこの規則で生成する（基準日から見て最も近い未通過のもの）。

## 5. 画面ごとのコンポーネントとコピー

### 5-1 splash（オンボーディング）

- 見出し: 「大切な日に、気づくアプリ。」
- サブ: 「誕生日・記念日・試験までの残り日数を、ウィジェットと通知で毎日思い出させます。」
- 通知許可カード: タイトル「通知を許可しますか？」/ 本文「当日・7日・3日・1日前に、大切な日をお知らせします。いつでも設定で変更できます。」
- ボタン: 「通知を許可する」/「あとで許可する」/「サンプルイベントを見る」

### 5-2 home（一覧）

- ヘッダー左: ブランドマーク（グラデ 135deg brand→custom）+「Anniv」/ 右: ウィジェットボタン・設定ボタン
- サブ日付: 「8月30日（日） — 今日も、大切な日が近づいています」（日次で更新）
- タブ: すべて / 家族 / カップル / 推し活 / 大事な日（アクティブ=ink 塗り、右端フェード）
- カード構成（左→右）: 種別色アクセントバー(5px)・アイコン賽箱 46px・タイトル + ピル（hot=「あと7日」等・種別）・右寄せ大数字+単位+ラベル（COUNTDOWN / ELAPSED）・シェブロン
  - daysLeft 表示: `N` `日後`/`日`　・ daysSince 表示: `+N` `日目`（ラベル ELAPSED）
- 下部: AD バナー枠（破線プレースホルダー「AD · バナー広告（AdMob 設置予定）」）
- FAB: 58px・brand グラデ・24px 白 `+`・右下（バナー上に配置）

### 5-3 新規作成（5 ステップ）

- 共通: ステップ表示「STEP n/5 — 新規作成」+ 進行ドット5個 / 下段「戻る（キャンセル）… 次へ（保存）」
- ①テンプレート: 2 列グリッド 6 種（§3-2）。選択でアクセントリング
- ②日付: セグメント「単発/毎年繰り返す」、9月2026 カレンダー（月曜始まり、`today` 枠、選択=brand 塗り）、クイックチップ（今日/1週間後/1ヶ月後/年末年始）、旧暦トグル（無効・「v2 で対応予定」）
- ③カウント方法: 3 択（残り日数 `あと 19 日` / 経過日数 `+110 日目` / 次の繰り返しまで）
- ④通知: 「当日/1日前/3日前/7日前」行（各行: ラベル+時刻+トグル）、マイルストーン通知トグル
- ⑤見た目: 背景プレビュー（種別色グラデ、大数字+タイトル+日付）、背景色スウォッチ 6 種、アイコン 5 択、背景写真トグル、保存

### 5-4 detail（詳細）

- ヒーロー（種別色グラデ 135deg + ドットグロー）: 大数字 76px + 単位、タイトル 21px、日付 + グループピル、マイルストーンピル「🎌 次のマイルストーン あと32日で 90日前」（ガラス風）
- アクション 4 列: 編集 / 共有（画像化）/ 非表示 / 削除（削除のみ danger 色）
- 基本情報: グループ・カウント方法・繰り返し・登録日
- 通知スケジュール: 当日 / 1日前 / 3日前 / 7日前 ＋ 時刻
- マイルストーン一覧: アイコン + 名称 + 日付 + 状態（通過済み=淡色チェック / あと N 日）

### 5-5 widget（ウィジェット設定）

- セグメント: 中サイズ（4件）/ 小サイズ（1件）
- プレビュー（青グラデ壁紙上）: ヘッダー（日付+時刻+Wi-Fi/バッテリ）+ 最大 3〜4 行（各: 種別色アイコン + タイトル + 日付 + 「あと N 日」）
- 解説: ①ホーム画面を長押し → ＋ → 「Anniv」を選ぶ ②更新タイミング（アプリを開いたとき・日付が変わったときに自動更新。v1 は次回起動時反映）

### 5-6 settings（設定）

| グループ | 行 | 値 / アクション |
|---|---|---|
| 通知 | 既定の通知時刻 | 09:00 |
| 通知 | 表示形式 | 残り日数（/ 日付） |
| 通知 | 週の開始曜日 | 月曜 |
| テーマ | ダークモード | トグル（全画面即時反映） |
| データ | バックアップ | JSON 書き出し（`Backup.json`） |
| データ | 復元 | ファイル選択 |
| アプリ | 広告を除去する | 買い切り ¥800（バナー除去） |
| アプリ | バージョン | 0.1.0 |

## 6. Flutter 実装メモ（実装計画との対応）

- **フォント**: `google_fonts` で `zenKakuGothicNew` / `outfit` をテーマ登録（Web フォント依存を外すため assets同梱も可）
- **トークン**: `data/design-tokens.json` → `AppColors` / `AppSpacing` / `AppTextStyle`（ThemeExtension 推奨、dark は `ThemeData.dark` と切替）
- **モデル**: `data/sample-events.json` = 計画 §04 `Event` スキーマに対応（id: string UUID、notifications[]: offsetDays 0/1/3/7 + time、milestones[]: int[]、countMode: daysLeft|daysSince|repeatNext）
- **計算ロジック**: daysLeft = targetDate(次回発生日) − today / daysSince = today − targetDate / repeat:yearly は 2/29 を平年 2/28 扱い
- **ウィジェット**: 中サイズ 4 件=計画 §06 の「ホーム画面ウィジェット 1 種」に相当。iOS は App Group + Widget Extension、Android は RemoteViews 方式
- モック内の日付・文言はすべてこの文書と JSON が正（画像内のマイナー文言差は撮影時のレイアウト都合）
